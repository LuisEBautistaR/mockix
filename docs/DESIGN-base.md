# Design System: Sendix

## Overview

**Creative North Star: "The Stone Workbench"**

Sendix is a working API client laid out on a quiet bench of three stones. The shell is the standard one a developer already knows (title bar, activity rail, collection tree, tab strip, request line, request and response side by side, status bar), and the system refuses to decorate it. The grounds are warm greys taken from the protohub.digital family; the type is Archivo at 12 to 13px with JetBrains Mono wherever the user reads something they typed or something the server sent. Colour is spent only where it means something: the grey-green on the one action that sends, the earth inks on methods and statuses, the syntax inks inside code.

Density is high and calm at the same time. Rows are 26 to 30px, controls 24 to 32px, panes have a 12px gutter, and every pane is filled with real context (resolved request, inherited auth, recent runs, saved messages, the service definition) rather than left as empty field. Hierarchy comes from weight steps (400, 500, 600, 650) and tone steps (ink, muted, faint), never from size: nothing in the window is larger than the 15px wordmark.

The signature is the strata bar: the timing breakdown of a response (DNS, TCP, TLS, wait, download; or handshake phases for WebSocket and gRPC) drawn as stacked stone layers under the status line, with every phase named and timed in mono beneath it. The system rejects the neon-on-black "hacker" client and the white SaaS dashboard.

**Key Characteristics:**
- Three warm stone grounds per theme; depth by tone step and 1px lines, no shadows on the shipped surfaces.
- One action colour (grey-green), used on Send/primary actions, the current-selection tint and the focus ring only.
- Archivo for all UI text, JetBrains Mono for code, URLs, numbers and method names, ligatures off.
- Fixed px type ramp from 11px to 15px; the wordmark is the largest text in the window.
- Methods and statuses carry muted earth inks and always their own text label.
- Light and dark themes are token-for-token mirrors; both hold WCAG AA.

## Colors

A palette of warm stones with one grey-green for action and a set of muted earth inks that only ever sit next to a word that says the same thing.

Every token exists twice: the light value on `:root` and a `-dark` sibling on `:root[data-theme="dark"]`. Components reference the light key; the theme switch swaps the whole set.

### Primary
- **Workbench Grey-Green** (`accent`, #5c6b54 in both themes): the fill of the primary button only (Enviar / Send, the composer's small Send). White label (`accent-ink`, #ffffff) on it.
- **Pressed Moss** (`accent-hover` #53614c light / #67785e dark; `accent-press` #4d5a46 light / #536049 dark): hover and active fills of the primary button. In light the hover darkens; in dark it lightens, so the step always moves away from the ground.
- **Selection Moss** (`select`, rgba(92, 107, 84, 0.16) light / rgba(142, 163, 131, 0.2) dark; `select-ink` #3f4b39 / #c9d6c1): the translucent tint behind the current rail item, the selected tree row, the selected stream message and text selection. `select-ink` is the label colour on that tint for rail and tree.
- **Focus Moss** (`focus`, #5c6b54 light / #9db091 dark): the 2px focus outline and the focused URL box border. Lightened in dark so the ring holds contrast on deep stone.

### Neutral
- **Rail Stone** (`rail`, #e4e1dd light / #1d1c1b dark): title bar, activity rail, sidebar, tab strip and status bar. All chrome sits on this ground.
- **Workbench Stone** (`work`, #eeecea light / #242322 dark): the main work area behind request and response, the selected tab, and the inset command search and environment picker.
- **Field Stone** (`field`, #f7f6f4 light / #2a2927 dark): editors and wells: URL box, code blocks, script editor, message detail, pressed segment, checkbox, secondary button.
- **Hover Wash** (`hover`, rgba(51, 50, 49, 0.06) light / rgba(233, 230, 226, 0.06) dark): the only hover fill for rows, tabs, rail and icon buttons.
- **Seam** (`line`, #d5d0ca light / #363431 dark): every 1px divider, table rule and control border.
- **Strong Seam** (`line-strong`, #bfb8af light / #4a4742 dark): hover border of inset controls, secondary button border, tag outline, scrollbar thumb.
- **Charcoal Stone** (`ink`, #333231 light / #e9e6e2 dark): primary text, the selected subtab underline and the checked checkbox fill.
- **Weathered Ink** (`muted`, #57534f light / #b0aaa3 dark): secondary text: inactive tabs and subtabs, column heads, descriptions, metrics labels, status bar; also the border of the unchecked checkbox, where Strong Seam would fall below 3:1. Kept visibly darker than Faint Ink so the ink, muted, faint steps stay distinct in light.
- **Faint Ink** (`faint`, #66615b light / #9a948c dark): tertiary text: line numbers, counts, chevrons, timestamps of system rows, placeholders, sizes.
- **Variable Amber** (`var-bg` rgba(131, 90, 23, 0.12) / rgba(213, 165, 90, 0.16); `var-ink` #6e4b12 / #e2bd80): the `{{variable}}` chip wherever an environment or collection variable appears (URL, code, tables, sidebar variables).

### Method Inks
Muted earth inks, one per protocol verb, always set in JetBrains Mono beside the verb itself: `m-get` (#176a77 / #7fb7c0) teal, `m-post` (#8a5a0c / #d9aa5e) ochre, `m-put` (#4249a6 / #a3aae6) slate blue, `m-patch` (#7346a0 / #bea6da) heather, `m-delete` (#a33a2c / #ec9283) brick, `m-ws` (#4f6115 / #b8c47e) lichen, `m-sio` (#5f5c12 / #c9c27a) olive, `m-grpc` (#8e3a72 / #d79ac0) plum. Used in the tree, the tab strip and the method selector of the request line.

### Status Inks
- **Pass Green** (`ok` #2d6844 / #8fcaa0; `ok-bg` tint): success statuses (2xx, 101, 1000 Normal, 0 OK), passing tests, the "connected" state chip, the engine-ready dot, passing test counts.
- **Fail Brick** (`err` #a1362a / #f09385; `err-bg` tint): error statuses (4xx, 1006, 14 UNAVAILABLE), failing tests and their reason block, console errors, failing test counts.
- **Neutral status** (`ink`): statuses that are neither success nor failure, such as gRPC "1 CANCELLED", stay in plain ink with no status colour.

### Syntax
Code inks for JSON, JavaScript, proto and raw HTTP, all on Field Stone: `syn-key` (#1f6f7c / #8fc3cb) keys and header names, `syn-str` (#8c5514 / #dcb489) strings, `syn-num` (#2d5ea8 / #a5bde6) numbers, `syn-lit` (#a3345a / #e6a0b5) true/false/null, `syn-kw` (#7440a3 / #c6a8e0) keywords and the HTTP verb, `syn-com` (#6f6a64 / #9c968e, italic) comments, `syn-punct` (same value as `syn-com`) braces, commas and colons.

### Strata
Five stone layers for the timing bar, from lightest to darkest in light (`strata-1` #d6cdc1, `strata-2` #c3b8aa, `strata-3` #a99d8e, `strata-4` #6f675f, `strata-5` #4a4540) and from darkest to lightest in dark (#3d3a36, #524d47, #6b655d, #8f877c, #b9afa2). Earlier phases are the pale top soil; later phases sink into dense stone.

### Named Rules
**The Green Means Act Rule.** Grey-green appears in exactly three roles: the primary action fill, the selection tint, and the focus ring. Never on headings, icons at rest, borders, links or decoration.

**The Ink Plus Word Rule.** A method ink or status ink never travels alone. Every coloured method carries its verb (GET, POST, WS, gRPC), every coloured status carries its code and phrase (200 OK, 1006 Anormal), every test result carries APROBADO / FALLIDO and an icon. Method inks are AA only on the three stones: on the selection tint the verb switches to `select-ink`.

**The Earned Colour Rule.** Pass Green marks success only and Fail Brick marks failure only. Any other outcome (cancelled, pending, informational) is set in neutral ink.

**The Three Stones Rule.** Surfaces come only from Rail, Workbench and Field stone. Chrome on Rail, working area on Workbench, anything the user types into or reads code from on Field. No fourth surface colour, no tinted panels.

## Typography

**UI Font:** Archivo (with system-ui, sans-serif), variable width axis, normal width (`wdth` 100) everywhere except the wordmark.
**Mono Font:** JetBrains Mono (with ui-monospace, Consolas, monospace), weights 400 and 500.

**Character:** Archivo is a sturdy grotesque that stays legible at 12px and gives the protohub family its voice; JetBrains Mono marks everything that is data rather than interface. The pairing reads like labels on a toolbox: plain words in Archivo, the contents in mono.

### Hierarchy
- **Wordmark** (800, 15px, condensed `wdth` 62, uppercase, 0.04em): "SENDIX" at the left of the title bar. The largest text in the window and the only condensed or uppercase Archivo.
- **Title** (650, 13px): sidebar heading ("Colecciones"), variables heading.
- **Body Strong** (600, 13px): status phrase on the response line, collection names in the tree, buttons, selected subtab.
- **Body** (400, 13px, line-height 1.45): tree rows, tabs, subtabs, test names (500), general UI text.
- **Section Label** (650, 12.5px) with an inline **Body Small** (400, 12.5px, muted) qualifier: in-pane section heads such as "Petición resuelta  lo que se enviará…". Section heads never exceed 12.5px.
- **Body Small / Body Small Strong** (400 / 600, 12.5px): table cells, command search, environment picker, saved messages, state chip, test summary counts.
- **Label / Column Head** (400 / 500, 12px): segmented controls, hints, link buttons, status bar, table column heads.
- **Tag** (500, 11px, 0.01em): outlined tags ("secreto", "stream del servidor", "Datos de ejemplo").
- **Code** (mono 400, 12px / 19px): code blocks, editors, key/value keys and values, message stream rows, console.
- **Mono URL** (mono 400, 12.5px): the URL in the request line and the gRPC method selector.
- **Mono Status / Mono Figure** (mono 500, 13px / 12.5px): the numeric status code and metric values (142 ms, 3,2 KB).
- **Mono Tag / Mono Meta** (mono 500 / 400, 11px): method verbs, keyboard hints, test result words, tree counts, subtab counts, strata legend.

### Named Rules
**The Wordmark Ceiling Rule.** No text is larger than the 15px wordmark, and no heading is larger than 13px. Hierarchy is made with weight (400, 500, 600, 650) and tone (ink, muted, faint), not size. All sizes are fixed px; nothing scales with the viewport.

**The 11px Floor Rule.** Nothing is set below 11px, in either font. Counts, kbd hints and legends sit exactly at the floor.

**The Typed-As-Typed Rule.** JetBrains Mono runs with ligatures and contextual alternates off (`calt` 0, `liga` 0), so `=>`, `!=` and `//` read exactly as typed; numbers, times and sizes stay in mono so they align in columns.

## Layout

A fixed desktop shell on a CSS grid: rows of 38px title bar, flexible body, 24px status bar; columns of 44px activity rail, 264px collection sidebar, flexible main area. The window has a minimum width of 1100px and no responsive breakpoints; reference frame is 1440×900.

Inside the main area, a 34px tab strip and a 48px request line (32px controls with 8px vertical padding) sit above a two-pane split: request editor 46%, response 54%, divided by a 1px seam. Each pane opens with a 34px subtab bar; the response pane first carries the response head (status line plus strata). Pane content uses a 12px horizontal gutter; toolbars are 8px × 12px.

Density follows a fixed set of heights: 24px (segmented control, mini select), 26px (tree rows, command search, environment picker, small buttons), 30px (key/value and stream rows), 32px (URL box, buttons, saved messages), 34px (tab strip, subtabs, rail buttons). Spacing steps are 2, 4, 6, 8, 10, 12, 14 and 16px, with 8px and 12px doing most of the work.

**The Filled Window Rule.** No large empty regions. When a pane's primary content is short, the remaining height is filled with real context in stacked sections (resolved request, inherited auth, recent runs, saved messages, negotiated connection, service definition, recent calls), each introduced by a Section Label and a 1px-ruled table or code block.

**The Shared Shell Rule.** HTTP, WebSocket, Socket.IO and gRPC use the same layout: same request line, same split, same response head with strata. Only the content of the panes changes.

## Elevation & Depth

The shipped window is flat. Depth is conveyed by stepping between the three stones (Rail chrome, Workbench work area, Field wells) and by 1px seams; the selected tab joins the work area by taking its colour and erasing its bottom seam. A `--shadow` token exists in the source (light: two soft charcoal shadows; dark: deeper black shadows) but no shipped surface applies it; it is held for floating layers the prototype does not yet show (menus, popovers).

**The Flat Stone Rule.** Surfaces at rest have no shadow. Separation comes from tone steps and 1px seams; a shadow is reserved for a layer that genuinely floats above the window.

## Shapes

Small, quiet corners throughout. Controls, rows, wells and code blocks use a 4px radius; small inline objects (kbd, tags, variable chips, checkbox, tab close button, failure reason, link buttons, focus outline) use 3px; the strata bar, its legend swatches and the subtab underline use 2px; status dots and the unsaved marker are circles. Borders are always 1px Seam or Strong Seam. Icons are 1.6px-stroke line icons with round caps and joins, at 14, 16 or 18px (rail).

### Response Head and Strata (Signature)
The response pane opens with the status line: the status code in Mono Status and the phrase in Body Strong, both in the status ink; then muted metric labels with ink Mono Figure values (Tiempo 142 ms, Tamaño 3,2 KB, Mensajes 38); actions at the right.

Under it sits the strata: an 8px bar with 2px radius on Workbench, its segments separated by 1px gaps and sized by duration, each filled with the stone layer of its position in the sequence. Below the bar, a wrapping mono 11px legend names every phase with a 8px stone swatch and its time in ink, and ends at the right with "total N ms" (preceded by a note such as "conexión reutilizada" when phases were skipped). Zero-length phases are omitted from both bar and legend, and later phases keep their deeper stone. The bar is `role="img"` with the full breakdown in its label; the legend always states every number in text.

**The Strata Rule.** The timing breakdown is always drawn as stacked stone layers under the status line, in the phase order of the protocol (DNS, TCP, TLS, wait, download for HTTP; handshake and upgrade phases for WebSocket and gRPC), and every layer is named and timed in the legend. The stones carry sequence, never status: no red or green inside the strata.

## Do's and Don'ts

### Do:
- **Do** keep every surface on one of the three stones per theme: Rail (#e4e1dd / #1d1c1b) for chrome, Workbench (#eeecea / #242322) for work, Field (#f7f6f4 / #2a2927) for wells and editors.
- **Do** reserve grey-green (#5c6b54) for the primary action, the selection tint and the focus ring.
- **Do** set all UI text in Archivo and all code, URLs, method verbs, numbers, sizes and timings in JetBrains Mono with ligatures off.
- **Do** keep type between 11px and 15px in fixed px, with headings at 13px or less and the 15px wordmark as the ceiling.
- **Do** pair every method and status ink with its text label, and every pass/fail with a word and an icon.
- **Do** switch method verbs to `select-ink` on a selected row, and set statuses that are neither success nor failure in neutral ink.
- **Do** fill tall panes with real context sections (history, resolved request, definitions) instead of empty field.
- **Do** draw response timing as the strata bar with a full mono legend and total.
- **Do** define every new colour as a light token and a `-dark` sibling, and check WCAG AA (4.5:1 for text, 3:1 for component boundaries and focus) on each ground it can sit on, including the Selection Moss tint.

### Don't:
- **Don't** use type larger than the 15px wordmark, or a heading larger than 13px.
- **Don't** set any text below 11px.
- **Don't** leave large empty regions in the window.
- **Don't** convey a method, status or test result by colour alone.
- **Don't** put grey-green on headings, links, icons at rest, borders or decoration.
- **Don't** add shadows to resting surfaces; separate with tone steps and 1px seams.
- **Don't** colour strata layers by status; the stones mean sequence.
- **Don't** introduce neon accents on black or a bright white SaaS ground; both themes stay in warm stone.
